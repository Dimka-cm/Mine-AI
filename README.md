# Minecraft RL Agent — пустая нейросеть на системе наград

Необученная нейросеть, которая учится крафтить в Minecraft на системе наград
с базой данных SQLite. Награда за правильную сборку рецепта, **затухание**
награды за повторы, отдельные счётчики для каждого тира материала и
**штрафы за неправильные действия**.

---

## Зрение: обучение координатам по картинке

Отдельный этап **до** обучения с подкреплением. Задача одна: по кадру понять,
где ты стоишь и куда смотришь. Это обучение с учителем — среда знает точные
координаты, с которых нарисован кадр, поэтому ответ известен заранее и
сходимость в десятки раз быстрее, чем через награды.

```
python3 pretrain_vision.py --samples 6000 --epochs 25     # обычный прогон
python3 pretrain_vision.py --quick                        # быстрая проверка
```

На вход идут **только пиксели** — никаких служебных чисел. Сеть учится читать:

| признак | что это |
|---|---|
| `x`, `z` | где агент стоит |
| `наклон` | смотрит вверх / прямо / вниз |
| `сторона света` | куда повёрнут, 4 класса |
| 4 расстояния до стен | впереди, справа, сзади, слева — в системе взгляда |
| 4 флага видимости | видно ли дерево / камень / железо / алмаз |

Результат прогона на 2000 кадрах (проверка на **новых** мирах):

| признак | ошибка | без обучения |
|---|---|---|
| сторона света | **80 %** | 25 % |
| наклон головы | 0.089 | 0.322 |
| x | 1.80 блока | 2.29 блока |
| z | 2.06 блока | 2.51 блока |
| стена впереди | 0.168 | 0.224 |

Обученные глаза переносятся в боевую модель:

```python
from pretrain_vision import load_into_brain
load_into_brain(brain, "vision.pt")   # -> RL стартует зрячим
```

Первый слой размножается по стеку кадров и делится на их число — средняя
яркость отклика сохраняется, активации на старте не зашкаливают.

### Компас: почему у стен разные материалы

Сначала зрение не училось вообще: сторона света определялась на 27 % при
случайных 25 %. Причина оказалась не в сети, а в постановке задачи — **у мира
не было видимой границы**, пол просто обрывался на краю. Когда границу
добавили одинаковым камнем, стало не лучше: в квадратной комнате с четырьмя
одинаковыми стенами вид на север и на юг совпадает до пикселя, и ориентация
неразрешима в принципе.

Поэтому у каждой стороны **свой материал** — видимый глазами компас:

| сторона | материал | цвет |
|---|---|---|
| −X | bedrock | тёмно-серый |
| +X | sand_block | песочный |
| −Z | gravel | крапчатый серый |
| +Z | dirt | коричневый |

Все четыре — недобываемые и непохожие, углы сведены к bedrock. Замер:
одинаковые стены → 27 %, разные → 54 %, после полного прогона → **80 %**.
Тест `test_walls_are_distinguishable` не даёт случайно унифицировать стены.

### Почему в свёртках нет усредняющего пулинга

`AdaptiveAvgPool2d` сжимает модель в разы, но он **намеренно инвариантен к
позиции** — усредняет признак по всей карте. Для Q-значений это терпимо, для
ориентации смертельно: «стена слева» и «стена справа» после усреднения
неразличимы. Замер на одних и тех же данных:

| последний слой | сторона света | параметров |
|---|---|---|
| `AdaptiveAvgPool2d(6×6)` | 27 % | 0.67 М |
| свёртка с шагом 2 | **84 %** | 4.83 М |

Поэтому карта признаков сжимается свёрткой с шагом 2 плюс 1×1 по каналам:
100 096 → 9 216 чисел на входе полносвязной части, позиция сохранена.
`PixelBrain` — **5 747 618** параметров (было 42.7 М). Тест
`test_vision_encoder_keeps_position` следит, чтобы пулинг не вернулся.

### Сколько это занимает

На RTX 3060 Laptop, узкое место — **сбор кадров на CPU**, не обучение:

| прогон | ОЗУ | сбор | обучение | итого |
|---|---|---|---|---|
| 6 000 × 25 эпох | 2.1 ГБ | 1.6 мин | 0.5 мин | **~2 мин** |
| 12 000 × 30 эпох | 4.3 ГБ | 3.1 мин | 1.3 мин | **~4.5 мин** |
| 20 000 × 30 эпох | 7.2 ГБ | 5.2 мин | 2.1 мин | **~7 мин** |

Кадр 426×240 весит 307 КБ, поэтому скрипт считает расход ОЗУ **до** сбора и
останавливается с подсказкой, если не влезает (`--ram-limit`, по умолчанию
1200 МБ).

## Обучение на пикселях: зрение + награды вместе

`train.py` обучает **символьную** модель `CraftBrain` — она видит мир числами.
Обученные глаза из `pretrain_vision.py` относятся к **пиксельной** `PixelBrain`,
и подключить их было некуда: цикла на пикселях не существовало. `train_pixel.py`
закрывает этот разрыв.

```
python3 pretrain_vision.py --samples 6000 --epochs 25    # 1. научить глаза
python3 train_pixel.py --episodes 5000 --vision vision.pt # 2. учить на наградах
python3 train_pixel.py --smoke                            # быстрая проверка
```

Что соединяется внутри:

| часть | роль |
|---|---|
| `PixelVisionEnv` | мир картинкой, инвентарь названиями |
| `PixelBrain` | свёртки-глаза + эмбеддинги предметов |
| `PixelReplayBuffer` | хранит одиночные кадры, стек собирает при выборке |
| `vision.pt` | старт не со случайных весов |

Полезные флаги: `--freeze-vision N` не трогает обученные свёртки первые N шагов,
пока головы не осмыслятся; `--buffer-on-disk` держит кадры в файле, а не в ОЗУ;
`--train-every 4` — стандартное для DQN соотношение обучения к сбору.

Двойной DQN здесь обязателен: действие выбирает обучаемая сеть, оценивает
целевая. Если их перепутать, Q систематически завышается — это один из пяти
каналов галлюцинаций. Тест `test_double_dqn_target_uses_both_nets` за этим следит.

**Минимальный размер кадра — 96×72.** Ниже свёртки не складываются: после
четырёх слоёв остаётся 2×4, и ядро 3×3 туда не влезает. Падает сразу
в конструкторе, а не в середине обучения.

## Язык: понимание команд и честные ответы

`brain/language/` — агент принимает команды по-русски и объясняет, что делает.

```
python3 talk.py
  вы: сделай каменный меч
  агент: понял, цель: stone_sword
  вы: что ты делаешь
  агент: нужно ещё 1 каменный меч
  вы: спой песню
  агент: не понял, скажите иначе
```

| часть | что | размер |
|---|---|---|
| `vocab.py` | словарь предметной области + русские команды | **334 токена** |
| `head.py` | понимание команд, выбор реплики | **81 500 параметров** |

Против 42.7 млн у зрения — язык занимает 0.2% модели.

### Почему галлюцинаций тут быть не может

Агент **не сочиняет текст**. Он выбирает реплику из набора и подставляет
числа, взятые прямо из наблюдения. Сказал «здоровье 5 из 20» — значит, в
`dense[SL_SURVIVAL]` ровно 5. Выдумывать попросту нечем.

Тестом закреплено и обратное: агент не должен рапортовать о драке, стоя
один в поле (`test_no_combat_talk_without_enemy`). Это та же галлюцинация
в миниатюре — фраза, не подтверждённая наблюдением.

Непонятую команду агент отклоняет («не понял, скажите иначе»), а не
угадывает наугад.

### Падежи

Русский — язык падежей: «брёвен», «бревну», «брёвнами» это одно понятие.
Эвристики на окончаниях здесь ломаются — доска/досок, камень/камня имеют
беглые гласные и чередования. Поэтому формы заданы **явной таблицей**
`FORMS`: их всего несколько десятков, и это надёжнее морфологического
анализатора. Все формы одного слова получают **один номер токена** — иначе
для сети это были бы разные слова.


## Экономика наград (перебалансирована)

Замер 60 эпизодов случайной политикой вскрыл перекос: **смерть −80 давала
−3040 из −4804 всех штрафов, то есть 63%**. Против них 167 очков плюсов —
соотношение 1 к 29. При таком раскладе градиент учит одному: не двигайся.

| правило | было | стало | почему |
|---|---|---|---|
| `survival.death` | −80 | **−25** | обрыв эпизода уже наказывает; −80 давал паралич |
| `survival.hurt` | −1.5 | **−0.4** | 420 ударов = −630, урон и так ведёт к смерти |
| `spatial.retreat` | −0.6 | **−0.15** | 928 срабатываний; отходить иногда необходимо |
| `world.gather_useless` | −0.8 | **−0.15** | агент не знает заранее, что блок бесполезен |
| `grid.place_wrong_cell` | −0.8 | **−0.4** | ошибка не должна стоить как катастрофа |
| `goal.completed` | пол 25, decay 0.80 | **пол 40, decay 0.92** | цель обязана оставаться самым выгодным событием |

Результат — честный тест «идеальная игра против случайной» (сборка меча):

| | итог эпизода |
|---|---|
| идеальная сборка | **+58.7** |
| случайные действия | −17.3 |
| **разрыв** | **+76.0** ← сигнал для обучения |

## Координаты

Раньше агент знал только направление взгляда и расстояние до верстака —
**где он находится, не знал вообще**. Добавлено 14 чисел (`SL_COORDS`):

| поле | что |
|---|---|
| 0–2 | x/y/z, нормированные размером мира |
| 3–5 | sin/cos угла на верстак + расстояние |
| 6–8 | sin/cos угла на точку спавна + расстояние |
| 9 | доля пройденных шагов эпизода |
| 10–13 | близость к четырём стенам мира |

Углы даются через sin/cos: иначе на переходе 359°→0° получается скачок,
который сеть воспринимает как телепортацию.

`DENSE_DIM` вырос 133 → **147**. Мост (`bot/bridge.js`) отдаёт координаты,
`play.py` строит из них те же 14 чисел — формат совпадает до числа.

### Именованные срезы

Тесты и мониторы резали хвост руками: `dense[-6:]`, `dense[-9:-6]`. Любое
новое поле молча ломало все такие места — именно так мост однажды и протух.
Теперь в `brain/spaces.py` есть `SL_INV`, `SL_HELD`, `SL_ORIENT`, `SL_GOAL`,
`SL_PAID`, `SL_CRAFT_STATE`, `SL_SURVIVAL`, `SL_COORDS` — границы считаются
из размеров и правятся автоматически.

## Ограничение по ядрам CPU

`brain/cpu_limit.py` резервирует ядра под пользователя, чтобы ноутбук
оставался отзывчивым во время обучения:

```python
from brain.cpu_limit import reserve_cores
reserve_cores(5)      # 5 ядер обучению, 6-е вам
import torch          # уже увидит ограничение
```

Работает на двух уровнях, и оба нужны: привязка процесса к ядрам
(`sched_setaffinity`, на Windows — через psutil) **и** ограничение потоков
в torch/numpy. Одного `torch.set_num_threads()` мало: OpenMP и MKL читают
свои переменные окружения, и выставлять их надо **до** импорта numpy.

Расклад на вашем i5-11400H: ядра 1–4 крутят среды, ядро 5 учит модель,
ядро 6 полностью ваше.

## Настоящие текстуры Minecraft

`tools/extract_textures.py` достаёт текстуры блоков прямо из .jar игры —
это обычный zip, декомпиляция не нужна:

```
python3 tools/extract_textures.py --jar "C:/.../26.1/26.1.jar"
python3 tools/extract_textures.py --auto        # ищет сам
```

Рендер подхватит `brain/env/textures.npz` автоматически; нет файла —
работает на процедурном зерне.

**Берутся только текстуры блоков мира.** Иконки предметов не трогаются
сознательно: инвентарь агент читает названиями, и дать ему картинки
предметов значило бы позволить угадывать крафт по виду иконки, минуя
чтение. Это была бы поблажка, а не обучение.


## Пиксельное зрение (гибрид)

Агент видит мир **картинкой**, как человек на экране, а инвентарь и сетку
крафта читает **названиями предметов**. Так и у человека: сундук видишь
глазами, но что внутри — читаешь подписями.

| канал | что это | размер |
|---|---|---|
| `pixels` | RGB от первого лица, стек 4 кадров | 4×3×240×426 |
| `grid` | сетка крафта, названия предметов | 9 |
| `dense` | инвентарь, здоровье, еда, цель, прогресс, координаты | 147 |
| `held` | предмет в руке | 1 |

Символьные карты мира (`voxels`, `blockmap`, `entmap`) по умолчанию
**выключены** — мир агент обязан читать глазами. Вернуть их можно флагом
`keep_symbolic_world=True` для сравнения двух режимов.

### Рендер

`brain/env/render.py` — raycaster на numpy, без OpenGL:

- **пол** рисуется floor-casting'ом, с сеткой швов между блоками — по ней
  видно расстояние и скорость;
- **блоки** — послойный марш лучей с проверкой глубины, боковые грани темнее;
- **мобы** — спрайты с проверкой глубины (прячутся за стенами), у враждебных
  тёмная «голова»: подсказка формой, а не только цветом;
- **туман** по расстоянию даёт CNN чувство глубины.

### Про «FPS» модели

Один кадр — фотография: по ней не понять, зомби бежит на тебя или от тебя.
Движение даёт **стек кадров**. Раньше модель видела ровно 1 кадр и была
слепа к движению полностью.

| FPS | skip | решений/с | 4 кадра охватывают |
|---|---|---|---|
| 120 | 1 | 120 | 33 мс |
| 120 | 4 | 30 | 133 мс |
| 60 | 4 | 15 | 267 мс ← как в Atari-DQN |

(пропуск кадров задаётся `frame_skip`)

`frame_skip` задаёт, сколько кадров мира приходится на одно решение. Все
кадры внутри пропуска попадают в стек: агент думает реже, но видит движение
целиком. Большой пропуск делает движение заметнее — за 33 мс зомби сдвинется
на 2 пикселя, за 267 мс на целый блок.

### Замеры (256×144, 16:9, стек 4)

Формат 16:9 — как в настоящем Minecraft. 4:3 был бы искажением кадра.

| | референс Minecraft | наш рендер |
|---|---|---|
| разрешение | 256×144, 16:9 | 256×144, 16:9 ✓ |
| цветов | 18 929 | **31 179** (среднее по 20 ракурсам) |
| детализация | 7.88 | **9.66** (минимум по кадрам 6.20) |

Фактуру дают процедурные текстуры 64×64 на грань: камень крапчатый, дерево
полосатое, руда во вкраплениях, трава пучками. Плюс направленный свет
(грани по X темнее граней по Z), ambient occlusion снизу вверх, градиент
неба и виньетирование. Без этого была плоская заливка: 655 цветов при
детализации 0.74 — по такой картинке CNN не оценит ни расстояние, ни
движение вдоль поверхности.

| что | 2 ядра Xeon | i5-11400H |
|---|---|---|
| рендер кадра | 5.55 мс | **1.6 мс (342 FPS)** |
| среда+рендер+стек | 7.86 мс | **4.1 мс (242 FPS)** |
| forward, батч 1 | 3.86 мс (CPU) | ~0.8 мс (RTX 3060) |

Палитру дают: процедурные текстуры 64×64 на грань, направленный свет
(грани по X темнее граней по Z), ambient occlusion по вертикали и поперёк
грани, облака суммой синусов, градиент неба, виньетирование и дизер ±4.6
уровня. Дизер важен отдельно: он добавляет оттенки, почти не повышая
детализацию, потому что меняется плавно между соседними пикселями.

Параметров модели: **13.8 млн**.

### Сколько FPS потянет ваш ПК

| режим | FPS | решений/с |
|---|---|---|
| одна среда, без пропуска | 242 | 242 |
| одна среда, skip 2 | 242 | 121 |
| одна среда, skip 4 | 242 | 61 |

Запрошенные 60 FPS проходят с запасом **×4**, 120 FPS — с запасом ×2.

Параллельно на 6 ядрах: **~1160 кадров/с** суммарно = 19 сред по 60 FPS
или 9 сред по 120 FPS. Параллельные среды — главный ускоритель обучения,
и упираются они именно в CPU, а не в видеокарту.

### Важно про VRAM на ноутбуке

В диспетчере задач RTX 3060 показывает «6.0 выделенной + 7.9 общей». Общая —
это **половина вашей ОЗУ**, а не вторая видеопамять; она не суммируется.
`nvidia-smi` показывает правду: `6144MiB`.

С драйвера 536.40 при переполнении VRAM NVIDIA не выдаёт ошибку, а молча
сливает данные в системную память — обучение замедляется в 5–10 раз без
предупреждения. Лечится один раз: **Панель управления NVIDIA → Управление
параметрами 3D → CUDA - Sysmem Fallback Policy → Prefer No Sysmem Fallback**.
Лучше внятный OOM, чем тихо ползущее обучение.

GPU 0 (Intel Iris Xe) для обучения бесполезен: CUDA на нём не работает.

## Правила добычи (как в ванили)

Уровень инструмента решает, выпадет ли дроп. Неподходящий инструмент ломает
блок **впустую** — ровно как в Minecraft:

| Блок | рука | дерев. кирка | камен. кирка | желез. кирка |
|---|---|---|---|---|
| `oak_log` | ✅ бревно | ✅ | ✅ | ✅ |
| `stone` | ❌ | ✅ булыжник | ✅ | ✅ |
| `iron_ore` | ❌ | ❌ | ✅ сырое железо | ✅ |
| `diamond_ore` | ❌ | ❌ | ❌ | ✅ алмаз |

Меч не заменяет кирку: `stone_sword` по камню даёт ❌. За разрушение руды
без нужной кирки — штраф `world.wrong_tool` (−2.0), потому что руда
уничтожена безвозвратно.

Цепочка прогрессии получается принудительной:
`рука → дерево → деревянная кирка → камень → каменная кирка → железо →
железная кирка → алмазы`.

## Зрение агента

Раньше агент видел куб 3×3×3 — буквально то, что под носом. Мобов он
замечал в момент удара и умирал вслепую. Теперь три канала:

| канал | размер | что даёт |
|---|---|---|
| `voxels` | 5×5×5 = 125 | ближнее 3D: что вплотную, куда можно шагнуть |
| `blockmap` | 13×13 = 169 | дальнее 2D сверху: **куда идти** — где лес, где руда |
| `entmap` | 13×13 = 169 | **где мобы** — отдельный слой, моб ≠ блок |

Обе карты повёрнуты по взгляду агента: «вперёд» всегда одно направление,
поэтому сети не нужно заново учить каждый поворот.

Плюс 6 чисел выживания в `dense`: здоровье, голод, броня, есть ли враг
рядом, дистанция до него, есть ли еда.

## Выживание

| правило | значение | смысл |
|---|---|---|
| `survival.death` | **−80.0** | смерть обрывает эпизод и обнуляет прогресс |
| `survival.hurt` | −1.5 | получил урон |
| `survival.kill` | +12.0 | убил моба — стало безопаснее |
| `survival.hit` | +1.5 | попал: учим доводить бой до конца |
| `survival.eat` | +6.0 | поел вовремя |
| `survival.eat_full` | −1.0 | сожрал еду будучи сытым |

Опасность **нарастает вместе с curriculum**: на целях «найти дерево»
враждебных мобов нет вовсе, иначе агент гибнет раньше, чем поймёт правила.
Дальше — по одному зомби на тир.

Баланс проверен замером: случайная политика умирает в 0% эпизодов на
нижних целях и в 70–76% на верхних — есть куда расти, но учиться есть на чём.

## Два канала награды

Требование «за повтор награду не давать» нельзя применять ко **всей** награде
сразу. Если обнулить и саму задачу, бездействие становится выгоднее крафта
(эпизод стоит −1.0 по step_cost, а цель давала бы +1.0) — агент честно учится
ничего не делать. Это реально случилось в первом прогоне. Поэтому каналы
разделены:

| Канал | Затухание | Зачем |
|---|---|---|
| **Задача** (`per_episode=True`) | внутри эпизода | плотный сигнал «делай дело»; спам-циклы не работают, но в новом эпизоде сигнал свежий |
| **Новизна** (сквозное) | навсегда | ровно то, что просил пользователь: первый меч +40, сотый — копейки, у каждого тира свой счётчик |

Цель (`goal.completed`) — **якорь обучения**: затухает с 60 до пола в 25,
который заведомо выше стоимости эпизода и любой серии штрафов.

## Как устроены награды

### 1. Сборка меча по шагам

Рецепт — это не «мешок предметов», а **форма на сетке 3×3**. Поэтому награда
растёт по мере того, как форма собирается:

```
Шаг 1: палка в слот 7 (рукоять)              +1.67
   +1.00  grid.place_correct     палка в клетке рецепта
   +0.67  grid.progress          прогресс 1/3

Шаг 2: доска НАД палкой                      +3.63
   +1.00  grid.place_correct
   +1.50  grid.place_adjacent    ← пространственная связь!
   +1.13  grid.progress          прогресс 2/3

Шаг 3: вторая доска сверху                   +9.95
   +1.00  grid.place_correct
   +1.50  grid.place_adjacent
   +1.44  grid.progress          прогресс 3/3
   +6.00  grid.shape_complete    ← форма собрана

Шаг 4: КРАФТ                                +125.00
  +25.00  craft.tool
  +40.00  craft.tool_first_ever  ← веха, один раз в жизни
  +60.00  craft.tier_up          ← новый тир материала
```

### 2. Затухание — спам больше не выгоден

```
деревянный меч #1:  +11.25  ███████
деревянный меч #2:   +5.06  ███
деревянный меч #3:   -1.72       ← уже в минус (антиспам-штраф)
деревянный меч #4:   -2.97
деревянный меч #5:   -3.50
```

Формула: `value = base_value × decay^times`, но не ниже `min_value`.
Счётчик `times` живёт в таблице `reward_state` и **переживает перезапуск**.

### 3. Новый тир — счётчик начинается заново

```
stone_sword    первый раз: +155.00  ███████████████████████████████
iron_sword     первый раз: +185.00  ██████████████████████████████████████
diamond_sword  первый раз: +215.00  ████████████████████████████████████████████
```

Ключ контекста `craft.tool|stone_sword` независим от `craft.tool|wooden_sword`,
поэтому выдохшийся деревянный меч не обесценивает каменный.

### 4. Штрафы за неправильные действия

| Событие | Штраф |
|---|---|
| Предмет в клетку, которой в рецепте нет | **−0.80** |
| Не тот предмет в правильную клетку | **−1.20** |
| Разрушил уже собранную часть формы | **−2.50** |
| Крафт несобранного рецепта | **−1.50** |
| Спам одним и тем же крафтом | **−4.00** |
| Уходит от цели / упёрся в стену | −0.60 / −0.50 |
| Каждый шаг (чтобы не тянул время) | −0.02 |

**Штрафы не затухают** (`decay=1.0`) — ошибка всегда стоит полную цену.

## Ориентация в пространстве

Модель видит мир **в системе координат своего взгляда**: локальный куб 3×3×3
вокруг агента поворачивается вместе с ним, поэтому «блок передо мной» — это
всегда один и тот же вход сети, независимо от стороны света.

Плюс отдельные награды: `spatial.face_target` (повернулся к верстаку),
`spatial.approach` / `spatial.retreat` (сократил / увеличил дистанцию),
`spatial.place_block_correct` (поставил блок куда надо).

## Схема базы наград

```sql
reward_rules   -- key, category, base_value, decay, min_value,
               -- max_repeats, one_shot, per_episode, description
```

Правила лежат **в данных, а не в коде** — можно менять баланс на лету:


### ⚠️ Версия игры — только 26.1

Если сервер всё же на 26.3 — поставьте **ViaVersion**, а бота подключайте
как 26.1-клиента.


### Четыре окна наблюдения

| порт | чем запускается | что показывает |
|---|---|---|
| 7860 | `dashboard.py` | живое обучение с нуля + разбор наград по шагам |
| 7861 | `monitor.py` | длинный прогон: лестница curriculum, графики, тиры |
| 7862 | `viewer3d.py` | 3D-вид агента в симуляторе, сетка крафта, инструмент |
| 7863 | `botmonitor.py` | **живая игра**: здоровье, еда, блоки вокруг, награды |

Все четыре можно держать открытыми одновременно.

```
Minecraft server  ←protocol→  bot/bridge.js  ←TCP JSON→  play.py
```

`bridge.js` отвечает только за «глаза и руки» (наблюдение и выполнение
действий), вся логика наград и обучения остаётся в Python. Формат наблюдения
идентичен симулятору, поэтому **веса переносятся между средами без
переобучения**.

### Что мост обязан повторять один-в-один

Это не косметика: рассинхрон на одно число — и обученная модель читает мусор.
Контракт закреплён тестами в `tests/test_bridge_contract.py` (13 штук).

| что | где | зачем |
|---|---|---|
| `ITEMS`, `BLOCKS` — тот же порядок | `bridge.js` ↔ `brain/spaces.py` | модель работает с числовыми id |
| вектор `dense` = 76 чисел | `play.py: bridge_obs_to_model` | `inv \| held(4) \| orient(6) \| goal \| paid(11) \| craft_state(3)` |
| `paid(11)` — память антифарма | `engine.paid_state()` | без неё среда немарковская, агент залипает в `place ↔ clear` |
| `craft_state(3)` | `table_open / has_3x3 / table_reachable` | агент должен видеть, какая сетка доступна |
| сетка 2×2 без верстака | `activeSlots()` в `bridge.js` | слоты 2,5,6,7,8 отклоняются мостом |
| `use_table` (действие 57) | `case 'use_table'` | единственный способ открыть 3×3 |
| `canHarvest()` | `bridge.js` | сообщает Python о `wrong_tool` для штрафа −2.0 |

### Проверка без сервера

```bash

node --check bot/bridge.js                          # синтаксис моста
```

## Модель

```
grid (9 слотов)   ─embed─→ ┐
voxels (27 блоков) ─embed─→ ├─→ MLP → features(256) ─┬─→ Dueling Q-head (DQN)
dense (инвентарь/ориентация/цель) ─→ ┘               └─→ Policy + Value (PPO)
```

- **411 342 параметра**, ортогональная инициализация, никаких предобученных весов
- У сетки крафта есть **обучаемый позиционный код** — слот 4 отличается от слота 7
- Тест `test_model_is_untrained` проверяет, что стартовая политика равномерная
- Две головы на общем стволе — можно переключаться между DQN и PPO

## Защита от фарма

За время отладки агент нашёл три способа получать награду, не выполняя задачу.
Все закрыты, на каждый есть регрессионный тест:

| Эксплойт | Что делал агент | Фикс |
|---|---|---|
| **Пересборка формы** | собрал → разобрал → собрал, `shape_complete` платил снова (+9392 за прогон, эпизоды без единого крафта) | веха оплачивается один раз за эпизод; клетки помечаются оплаченными |
| **Ходьба туда-сюда** | шаг к верстаку → шаг назад → повтор | potential-based shaping: платим только за **новый рекорд** близости |
| **Побочные рецепты** | случайно выкладывал доски, пока цель — палки | плотные награды только за рецепты из `prerequisites(цель)` |
| **Копание без дела** | ломал блоки ради `world.gather` | `max_repeats=4` за эпизод |

Отдельная тонкость — **баланс риска**. В сетке 3×3 примерно 7 клеток из 9
«не те». При награде +1.0 за верную клетку и штрафе −1.5 за ошибку
матожидание любой попытки отрицательное, и агент выучивает *вообще ничего не
класть*. Сейчас +3.0 / −0.8 даёт матожидание +0.04: пробовать выгодно,
ошибаться — нет.
